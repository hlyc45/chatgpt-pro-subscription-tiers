## 停售 19 天：额度为什么会被砍半

先补一条时间线，它能解释很多事：

- **9月3日**：GPT-6 Astra 发布，需求直接爆了；
- **9月9日**：OpenAI 首席产品官 Tibo Sottiaux 公开预警，称需求“前所未有”，可能暂停 Pro 新订阅；
- **9月10日**：200 美元档正式停售。官方给的理由是这一档给系统带来的压力最大：约 20 倍于 Plus 的用量，每 5 小时最多能跑 900 条 Astra 消息，单位美元的算力密度全场最高；
- **9月23日**：开了一道小门，9月10日持有 Pro 200 的用户可以在流失后 30 天内回来一次；
- **9月29日至30日**：DevDay 公布了三档结构（Pro 100 / Pro 200 / Pro 500），Pro 200 同步重开。

为什么非要动这一刀？研究机构 SemiAnalysis 估算过一个数字：一个被用到极限的旧版 Pro 200，按 API 价格折算相当于每月约 1.4 万美元的用量。用户只要消耗掉每周额度的 5.7%，这档订阅就在亏钱。Astra 时代的 Agent 任务动辄连跑几个小时、反复读写文件，这个阈值并不难碰到。补贴撑不住了，砍额度是最直接的办法。

## 现在的 Pro 200，200 美元能买到什么

按官方帮助中心的说明，Pro 订阅包含 Pro 模型、Codex、深度研究、图像生成、记忆和文件上传。具体到 200 美元这一档：

**用量部分**

- 聊天额度单独算：据 Engadget 等媒体报道，新订阅每周约 100 条 GPT-6 Pro 消息，旧额度是每周 200 条、外加每天 170 条 GPT-5.6 Sol Pro。官方没有公布各档聊天条数，这个数字以媒体口径为准；
- 套餐内额度用完可以买 credits 续，但 credits 只覆盖 Codex、ChatGPT Work 和 Word/Excel/PowerPoint，普通聊天补不了。

**规则部分**

- Pro 三档都没有 5 小时窗口，只按周重置。额度集中在一两天用完和摊开用，官方不做区分；
- Fast 模式按 2.5 倍消耗套餐内用量，Ultrafast 按 8 倍。但 Ultrafast 是 Pro 500 独占，Pro 200 上买再多 credits 也解锁不了，官方帮助中心写得很明确；

- Sign in with ChatGPT 可以把订阅额度带进 Devin、Notion、Vercel 等 16 个合作工具里消耗。

## “砍半”这笔账，官方和用户各算各的

OpenAI 的逻辑是这样的：GPT-6 Sol 和 Luna 的 API 价格降了一半（Sol 降到每百万 token 输入 2 美元/输出 10 美元，Luna 低到 0.1/0.5 美元），同样的美元额度能跑接近一倍的 token。额度砍半、模型降价，一来一回，能干的活大体不变。Sottiaux 还给了三个承诺：5 小时窗口永久废除；订阅用户每美元能买到的工作量只会随时间上升；订阅里会持续加入不占用额度的内容。

用户这边同样有一笔账：**Astra 的 API 价格一分没降**，还是输入 10 美元/输出 50 美元。如果你的 Pro 200 主要用来跑 Astra 的 Codex 长任务，美元额度减半意味着 Astra 可用量实打实少了一半。所以结论分人：

- **以 Sol/Luna 为主**：模型降价基本对冲了额度下调。Artificial Analysis 的实测显示，GPT-6 Sol 单任务成本已从 1.99 美元降到 1.06 美元，Luna 从 0.18 美元降到 0.07 美元，而且单任务生成的 token 量还在涨；
- **重度依赖 Astra**：净亏损。社区里“20X 变 10X”的说法，说的就是这群人。

还有个背景值得一提。改版前，Pro 200 是 20 倍用量，按官方月费折算每 1 倍 Plus 用量合 10 美元，比 Pro 100 便宜一半，这是重度用户选它的核心理由。改版后三档拉平，每 1 倍用量都约 20 美元（按各自月费和倍数折算）。Pro 200 不再是“量大打折”，它和 Pro 100 的区别只剩下用量本身。

最直接的判断方法是看用量页：用 Plus 的时候，每周大概第几天把额度用完？

## 开通之后：几个不浪费额度的习惯

10 倍用量说多不多、说少不少，用法差别很大：

- **聊天里省着用 GPT-6 Pro**。一周约 100 条，拿去问简单问题，周三就见底了。日常问答交给其他模型，GPT-6 Pro 留给真正值得的硬问题；
- **Codex 里按任务分模型**。主线开发用 GPT-6 Sol；批量重命名、补测试、写文档这类定义清晰的小活用 GPT-6 Luna，成本约是 Sol 的二十分之一；Astra 只留给最难的调试和长程 Agent 任务；
- **少开 Fast 模式**。2.5 倍的消耗速度不是开玩笑的，赶时间再开；
- **别重复喂上下文**。每个任务都重新粘贴整个文件、重新解释项目背景，都是在烧额度。同一会话里接着聊，缓存输入只按正常输入的 10% 计费；在仓库根目录放一份 AGENTS.md，Codex 每次运行都会读，就不用反复交代项目约定。
